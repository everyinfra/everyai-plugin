# EveryAI 清洗转型说明

> 生产EveryInfra MCP已在既有`everyinfra_chat`兼容工具之外提供来源绑定清洗。每次执行仍须先
> 通过实时发现确认两个清洗工具；工具存在不证明特定账户已达标、激活或完成端到端实测。

## 变化方向

EveryAI 当前通过通用聊天契约处理用户已经提供的文本。后续方向是把 EveryData 结果清洗迁到
独立、绑定站内来源的附赠权益，而不是把通用聊天改成免费，也不是静默改变
`everyinfra_chat` 的含义。

首期清洗政策已经确认用于实现：直客账户的可核净结算充值本金达到人民币 500 元后显式领取；
首期 30 天，每个 UTC 日最多 1,000 个成功单元，总计最多 30,000 个成功单元；同一账户每分钟
最多 5 次执行提交、最多 5 个并发执行单元。以上是计划契约，不是线上容量、永久权益或“无限
免费”的承诺。

清洗输入必须来自客户有权读取、仍未过期的 EveryData 结果，并使用服务端登记配方。它不接受
任意聊天历史、自定义 system prompt、模型选择、工具、外部 URL 或自由输出 schema。

## 已上线的 15 个操作

生产通过两个MCP工具提供15个操作。执行前仍须重新读取线上`tools/list`与schema。

| 工具 | 操作 | 用途 |
| --- | --- | --- |
| `everyinfra_data_cleanup_read` | `get_entitlement`、`get_source`、`get_source_fields`、`list_recipes`、`preview`、`list_jobs`、`find_job`、`get_job`、`list_units`、`get_result`、`export` | 查询资格/政策，发现来源版本和字段，预览固定配方，找回原任务，读取及导出终态结果。 |
| `everyinfra_data_cleanup_action` | `activate`、`submit`、`cancel`、`delete_result` | 显式开始权益周期、幂等提交任务、申请取消或删除结果正文。 |

执行时必须先调用 `tools/list`，确认两个工具实际存在，再读取返回的 `inputSchema`。未发现时，
`everyinfra_chat` 只继续处理用户自带普通文本；来源绑定清洗明确返回不可用，不能按本文拼请求。

### 刷新恢复与字段发现

- `list_jobs` 以有界游标列出当前账户来源尚未到期的任务。
- `find_job` 使用原提交幂等键，在未知回执或刷新后找回同一任务。幂等键不进入 URL 或分析事件；
  404 不能证明原提交从未受理，因此不能自动换新键重提。
- `get_source_fields` 返回有界推断字段路径和类型，不返回样例值。字段推断只帮助选择；必须保留
  返回的来源版本，真正可执行性仍由 `preview` 判定。

## 如何选择路径

| 请求 | 当前处理 | 清洗公开上线后 |
| --- | --- | --- |
| 处理用户已经提供的普通文本 | 只有实时 schema 仍提供 `everyinfra_chat` 且用户授权时才调用。 | 按届时公开的兼容或退役通知处理；清洗不是所有通用文本任务的等价替代。 |
| 清洗 EveryData 结果 | 先发现实时清洗契约，再核权益、来源版本和预览，最后按授权提交；不把通用聊天冒充清洗权益。 | 继续遵循同一来源绑定契约及届时的迁移通知。 |
| 可确定性规范化的数据 | 能用普通代码可靠完成时优先代码。 | 上线后也不强制每条数据经过模型。 |
| 核验当前事实 | 使用 EverySearch 或研究工作流。 | 清洗结果仍不能代替事实来源。 |

不得根据本文件猜清洗工具名或请求载荷。以生产 MCP `tools/list` 和公开 OpenAPI 为准；如果没有
发现清洗能力，就停止并说明当前不可用，不能把源数据改送通用聊天作为静默回退。

## 迁移顺序

1. 旧通用接口仍公开时，保留已有、已授权的 `everyinfra_chat` 调用；本文件不公布退役日期。
2. 区分“用户自带文本”与“EveryData 站内结果”两类调用。
3. 来源绑定请求先发现正式schema，并保留服务端签发的来源引用和版本。
4. 按发现、权益查询、预览、显式领取、幂等提交的顺序接入。
5. 提交结果未知时查询原操作，不换幂等键，也不切回通用聊天重做。
6. 只有在公布明确日期和兼容期后才退役旧集成；30 天迁移期与账户的 30 天清洗权益不是同一周期。

## 三层交付边界

- **Skill** 是工作方法和决策说明；修改 Skill 不会增加服务端能力。
- **MCP** 是线上工具连接和实时 schema；只有生产服务发现并执行清洗，才能宣称 MCP 可用。
- **Plugin** 是分发 Skill 与 MCP 元数据的可安装包；发布或安装插件不等于账户已获清洗权限。
